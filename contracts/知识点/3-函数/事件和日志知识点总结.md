## 基础概念

### 什么是事件（Events）？

事件是 Solidity 中用于记录合约执行过程中发生的重要操作的机制。事件数据会被记录到区块链的**交易日志**（Transaction Logs）中，但不存储在合约的状态变量中。

### 什么是日志（Logs）？

日志是以太坊虚拟机（EVM）的一个功能，用于记录合约执行期间的数据。事件触发后，相关数据会以日志的形式写入区块链。

### 为什么使用事件？

| 优势 | 说明 |
|-----|------|
| **便宜** | 日志存储成本比状态变量便宜约 8 倍 |
| **可追踪** | 前端 DApp 可以监听事件实时更新 UI |
| **可查询** | 可以通过事件查询历史操作记录 |
| **不可篡改** | 事件一旦记录就无法修改或删除 |
| **不占用状态** | 不增加合约的存储负担 |

### 限制

- ❌ 无法在合约内部读取事件数据
- ❌ 无法修改已触发的事件
- ❌ 不能用于合约逻辑判断

## 事件的定义和使用

### 基本语法

```solidity
// 定义事件
event EventName(type1 indexed param1, type2 param2, ...);

// 触发事件
emit EventName(value1, value2, ...);
```

### 完整示例

```solidity
contract EventExample {
    // 定义事件
    event Transfer(
        address indexed from,
        address indexed to,
        uint amount
    );
    
    // 触发事件
    function transfer(address _to, uint _amount) public {
        // 执行转账逻辑...
        
        // 触发事件
        emit Transfer(msg.sender, _to, _amount);
    }
}
```

### 事件命名规范

✅ **推荐**：
- 使用 PascalCase（首字母大写）
- 使用动词的过去式
- 清晰描述发生了什么

```solidity
event Transfer(...)       // ✅ 好
event Approval(...)       // ✅ 好
event NFTMinted(...)      // ✅ 好
event OwnershipTransferred(...)  // ✅ 好

event transfer(...)       // ❌ 不好（应该首字母大写）
event Transferring(...)   // ❌ 不好（应该用过去式）
event DoTransfer(...)     // ❌ 不好（不应该用动词原形）
```

## indexed 参数详解

### 什么是 indexed？

`indexed` 关键字使参数可以被**过滤和搜索**。indexed 参数会作为日志的 **topics**，非 indexed 参数存储在 **data** 中。

### Topics 结构

每个日志最多可以有 **4 个 topics**：
- **Topic 0**：事件签名哈希（自动）
- **Topic 1-3**：indexed 参数（最多 3 个）

### 使用规则

```solidity
// ✅ 最多 3 个 indexed 参数
event Transfer(
    address indexed from,     // topic 1
    address indexed to,       // topic 2
    uint amount              // data（不可过滤）
);

// ❌ 超过 3 个 indexed 会编译错误
event TooManyIndexed(
    address indexed a,
    address indexed b,
    uint indexed c,
    uint indexed d    // ❌ 第 4 个 indexed
);
```

### indexed 对不同类型的影响

| 类型 | indexed 行为 | 说明 |
|-----|-------------|------|
| `address` | 直接存储 | 可以直接过滤和读取 |
| `uint`, `bool`, `enum` | 直接存储 | 可以直接过滤和读取 |
| `string`, `bytes`, `array` | 存储 **keccak256 哈希** | ⚠️ 前端无法读取原始值！ |
| `struct` | ❌ 不支持 | 必须拆解为基本类型 |

### 示例：indexed 对 string 的影响

```solidity
event Log1(string indexed category, string description);
//                  ↑ 存储哈希值          ↑ 存储原始值

emit Log1("Sale", "NFT sold for 10 ETH");

// 前端监听时：
// - category: 只能看到哈希值，看不到 "Sale"
// - description: 可以看到 "NFT sold for 10 ETH"
```

### 何时使用 indexed？

✅ **应该使用 indexed**：
- 地址类型（`address`）- 用于过滤特定用户
- ID 类型（`uint tokenId`）- 用于过滤特定项目
- 枚举类型（`enum`）- 用于过滤特定状态

❌ **不应该使用 indexed**：
- 金额、数量等数值
- 时间戳
- 需要读取原始值的 string/bytes

```solidity
// ✅ 好的设计
event Transfer(
    address indexed from,     // 可以过滤特定发送者
    address indexed to,       // 可以过滤特定接收者
    uint amount,             // 不需要过滤，保留原始值
    uint timestamp           // 不需要过滤
);

// ❌ 不好的设计
event Transfer(
    address indexed from,
    address indexed to,
    uint indexed amount,     // 通常不需要按金额过滤
    uint indexed timestamp   // ❌ 超过 3 个 indexed
);
```

## 事件的 Gas 成本

### 成本分解

| 操作 | Gas 成本 |
|-----|---------|
| 基础日志成本 | 375 gas |
| 每个 topic (indexed) | 375 gas |
| 每字节数据 (data) | 8 gas |
| 状态变量存储 (SSTORE) | 20,000 gas（首次）/ 5,000 gas（更新） |

### 成本对比

```solidity
contract GasComparison {
    uint public storedValue;
    
    event ValueChanged(uint newValue);
    
    // 方法1：只存储（昂贵）
    function onlyStorage(uint _value) public {
        storedValue = _value;  // ~20,000 gas（首次）
    }
    
    // 方法2：只事件（便宜）
    function onlyEvent(uint _value) public {
        emit ValueChanged(_value);  // ~750 gas
    }
    
    // 方法3：两者都用（推荐）
    function both(uint _value) public {
        storedValue = _value;
        emit ValueChanged(_value);
        // ~20,750 gas（只比存储多 750）
    }
}
```

### Gas 优化技巧

#### 1. 减少 indexed 参数

```solidity
// ❌ 不好：过多的 indexed
event Transfer(
    address indexed from,
    address indexed to,
    uint indexed amount      // 通常不需要 indexed
);
// 成本：375 + 375*3 = 1,500 gas

// ✅ 好：只 indexed 必要的参数
event Transfer(
    address indexed from,
    address indexed to,
    uint amount
);
// 成本：375 + 375*2 + 32 = 1,157 gas
```

#### 2. 使用较小的数据类型

```solidity
// ❌ 如果值不大，使用 uint256 浪费
event SmallValue(uint256 value);

// ✅ 使用合适的类型
event SmallValue(uint8 value);  // 节省存储空间
```

#### 3. 批量操作使用批量事件

```solidity
// ❌ 不好：循环中多次触发
function batchTransfer(address[] memory recipients, uint[] memory amounts) public {
    for (uint i = 0; i < recipients.length; i++) {
        emit Transfer(msg.sender, recipients[i], amounts[i]);  // 每次都花费 gas
    }
}

// ✅ 好：一次性触发
event BatchTransfer(address indexed from, address[] recipients, uint[] amounts);

function batchTransfer(address[] memory recipients, uint[] memory amounts) public {
    emit BatchTransfer(msg.sender, recipients, amounts);  // 只触发一次
}
```

## 事件 vs 状态变量

### 决策指南

| 场景 | 推荐方案 | 原因 |
|-----|---------|------|
| 需要在合约中读取数据 | 状态变量 | 事件无法在合约中读取 |
| 只需记录历史，前端查询 | 事件 | 便宜得多 |
| 需要修改历史数据 | 状态变量 | 事件不可修改 |
| 数据量非常大 | 事件 | 节省存储成本 |
| 关键业务逻辑数据 | 状态变量 | 可靠性高 |
| 统计和分析数据 | 事件 | 便宜且可查询 |

### 混合方案示例

```solidity
contract MixedApproach {
    // 关键数据：状态变量
    uint public totalTransactions;
    mapping(address => uint) public balance;
    
    // 详细历史：事件
    event TransactionExecuted(
        address indexed from,
        address indexed to,
        uint amount,
        string description,
        uint timestamp
    );
    
    function transfer(address _to, uint _amount, string memory _desc) public {
        // 更新关键状态
        balance[msg.sender] -= _amount;
        balance[_to] += _amount;
        totalTransactions++;
        
        // 记录详细历史
        emit TransactionExecuted(msg.sender, _to, _amount, _desc, block.timestamp);
    }
}
```

## 事件的最佳实践

### ✅ DO（应该做）

1. **为重要操作定义事件**
   ```solidity
   function transferOwnership(address newOwner) public {
       address oldOwner = owner;
       owner = newOwner;
       emit OwnershipTransferred(oldOwner, newOwner);  // ✅
   }
   ```

2. **使用描述性的事件名称**
   ```solidity
   event NFTMinted(...)           // ✅ 清晰
   event TokenTransferred(...)    // ✅ 清晰
   ```

3. **在状态变更后触发事件**
   ```solidity
   function transfer(address to, uint amount) public {
       balances[msg.sender] -= amount;  // 先更新状态
       balances[to] += amount;
       emit Transfer(msg.sender, to, amount);  // 后触发事件
   }
   ```

4. **包含足够的上下文信息**
   ```solidity
   event OrderCreated(
       uint indexed orderId,
       address indexed buyer,
       uint amount,
       uint timestamp  // ✅ 包含时间戳
   );
   ```

5. **对需要过滤的参数使用 indexed**
   ```solidity
   event Transfer(
       address indexed from,    // ✅ 可以按用户过滤
       address indexed to,      // ✅ 可以按用户过滤
       uint amount             // 不需要过滤
   );
   ```

### ❌ DON'T（不应该做）

1. **不要在事件中存储敏感信息**
   ```solidity
   event UserRegistered(
       address user,
       string email,           // ❌ 隐私信息
       string passwordHash     // ❌ 即使是哈希也不应公开
   );
   ```

2. **不要过度使用 indexed**
   ```solidity
   event Transfer(
       address indexed from,
       address indexed to,
       uint indexed amount,    // ❌ 通常不需要
       uint indexed timestamp  // ❌ 超过 3 个
   );
   ```

3. **不要用事件代替状态变量**
   ```solidity
   function setVerified(address user) public {
       emit UserVerified(user);  // ❌ 只有事件，没有状态
       // verified[user] = true;  // ✅ 应该同时更新状态
   }
   ```

4. **不要在循环中触发大量事件（如可避免）**
   ```solidity
   for (uint i = 0; i < 1000; i++) {
       emit ItemProcessed(i);  // ❌ 可能导致 gas 过高
   }
   ```

5. **不要忘记使用 emit 关键字**
   ```solidity
   Transfer(from, to, amount);       // ❌ Solidity 0.5+ 会报错
   emit Transfer(from, to, amount);  // ✅ 正确
   ```

## 常见问题和解决方案

### Q1: 为什么我的事件在合约中读取不到？

**A:** 事件数据存储在日志中，无法在合约内部读取。如果需要在合约中使用数据，必须使用状态变量。

```solidity
// ❌ 错误：尝试读取事件
function checkTransfer(address user) public view returns (uint) {
    // 无法读取 Transfer 事件
}

// ✅ 正确：使用状态变量
mapping(address => uint) public totalSent;

function transfer(address to, uint amount) public {
    totalSent[msg.sender] += amount;  // 存储在状态变量中
    emit Transfer(msg.sender, to, amount);  // 同时触发事件
}
```

### Q2: indexed string 参数为什么前端看到的是哈希值？

**A:** string/bytes/array 类型的 indexed 参数会被哈希存储，前端只能看到哈希值，看不到原始值。

```solidity
// ❌ 不好
event Log(string indexed category);  // 前端只能看到哈希值

// ✅ 好
event Log(string category);  // 前端可以看到原始值

// ✅ 或者：既要过滤又要原始值
event Log(bytes32 indexed categoryHash, string category);
emit Log(keccak256(bytes("Sale")), "Sale");
```

### Q3: 如何查询特定用户的所有转账记录？

**A:** 使用过滤器查询 indexed 参数。

```javascript
// 前端代码
const userAddress = "0x...";

// 查询用户发出的所有转账
const sentFilter = contract.filters.Transfer(userAddress, null);
const sentEvents = await contract.queryFilter(sentFilter, 0, "latest");

// 查询用户收到的所有转账
const receivedFilter = contract.filters.Transfer(null, userAddress);
const receivedEvents = await contract.queryFilter(receivedFilter, 0, "latest");
```

### Q4: 事件触发失败会导致交易回滚吗？

**A:** 正常情况下不会，但如果 gas 不足则整个交易会失败。

```solidity
function transfer(address to, uint amount) public {
    balances[msg.sender] -= amount;
    balances[to] += amount;
    
    emit Transfer(msg.sender, to, amount);  // 如果这里 gas 不足，整个交易会失败
}
```

### Q5: 如何处理大量历史事件的查询？

**A:** 使用分批查询避免超时。

```javascript
async function queryInBatches(eventName, fromBlock, toBlock) {
    const batchSize = 5000;
    const events = [];
    
    for (let start = fromBlock; start <= toBlock; start += batchSize) {
        const end = Math.min(start + batchSize - 1, toBlock);
        const batch = await contract.queryFilter(eventName, start, end);
        events.push(...batch);
    }
    
    return events;
}
```

### Q6: 事件可以有重载吗？

**A:** 可以，但必须保证事件签名不同。

```solidity
// ✅ 可以：参数不同
event Transfer(address indexed from, address indexed to, uint amount);
event Transfer(address indexed from, address indexed to, uint amount, string memo);

// ❌ 不行：签名相同
event Transfer(address indexed from, address indexed to, uint amount);
event Transfer(address indexed sender, address indexed recipient, uint value);
```

### Q7: 匿名事件什么时候使用？

**A:** 匿名事件（anonymous）节省一个 topic 位置，允许 4 个 indexed 参数，但更难过滤，很少使用。

```solidity
event NormalEvent(address indexed a, address indexed b, uint indexed c);
// Topics: [EventSignature, a, b, c]

event AnonymousEvent(address indexed a, address indexed b, uint indexed c, uint indexed d) anonymous;
// Topics: [a, b, c, d]  - 没有事件签名，可以有 4 个 indexed
```
